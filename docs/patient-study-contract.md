# 가상 환자와 검사 식별 규칙 제안

Issue #25에서 팀 공유 통합 설계서의 식별 관계를 따르는 개발용 저장 계약이다. 화면 연결과 DICOM 파일 처리는 아직 포함하지 않는다.

- 환자는 발급 주체와 환자 ID의 쌍으로 구분한다. 허용된 연구 ID도 명시적인 발급 주체를 함께 사용한다.
- 이름은 환자 식별 근거로 사용하지 않는다. 같은 이름이더라도 발급 주체나 ID가 다르면 다른 식별 정보다.
- 검사 ID와 확인된 환자 식별 정보를 함께 전달한다. 같은 검사 ID가 다른 환자에 이미 연결돼 있으면 기존 연결을 변경하지 않고 충돌을 알린다.
- 식별자는 앞뒤 공백만 제거한다. 대소문자를 임의로 바꾸거나 중간 공백을 제거하지 않는다. 빈 값과 제어문자, 128자를 넘는 값은 거절한다.
- 현재 검사 ID는 각 사용자 안에서 유일하게 다룬다. 이 범위와 DICOM Study Instance UID와의 관계, 공유 구조와 정정 권한은 팀 합의가 필요하다. 이 코드는 DICOM UID의 유효성이나 전체 시스템에서의 유일성을 검증하지 않는다.
- 서로 다른 검사 ID는 동일 검사의 재연결 검사로 취급하지 않는다.
- 설계서 기준 검사 하나는 환자 하나에, 시리즈 하나는 검사 하나에, 원본 객체 하나는 시리즈 하나에 연결한다. 시리즈나 원본이 아직 없는 검사도 허용한다. 환자와 검사 관계는 부록 B, 원본 등록과 UID 충돌 기준은 9.2와 UC02에 기술되어 있다.

현재 코드는 `PatientIdentity`, `StudyIdentity`, `validate_study_patient`를 제공한다. 같은 검사를 같은 환자에 다시 연결하는 검사는 통과하고 다른 환자와의 연결은 `StudyPatientConflict`를 발생시킨다. 오류 메시지에 환자 이름이나 ID를 넣지 않는다.

`patient_study_store.py`는 환자와 검사 식별 정보를 저장하고 단건 및 페이지별 목록을 조회한다. 이미 존재하는 검사를 다른 환자에 연결하려는 요청은 기존 데이터를 변경하지 않는다. 환자 정보는 검사보다 먼저 저장해야 한다. 식별 정보는 변경하거나 삭제하지 않는다.

`study_details_store.py`는 촬영일과 환자 연결 상태, 영상 수신 상태를 별도로 저장하고 조회한다. 날짜는 `YYYY-MM-DD` 또는 미상이다. 영상 개수나 환자 연결 확인만으로 수신 완료를 추정하지 않으며 완료 근거와 상태 소유자가 정해질 때까지 수신 완료 표시는 저장하지 않는다. 수정 시 이전에 읽은 문서의 `updateTime`을 전달해 앱 클라이언트에서 동시 수정 충돌을 감지한다. 규칙 파일은 같은 검사에 대한 본인 수정만 허용하지만 임의 클라이언트의 버전 확인 강제까지 보장하지 않는다.

Firestore 규칙 파일에 본인만 읽고 생성할 수 있는 경로를 추가했다. 규칙은 아직 서버에 배포하지 않았고 실제 Firebase에서 저장이나 권한 차단을 검증하지 않았다. 해시로 만든 문서 ID는 개인정보 암호화 수단이 아니다. 실제 환자정보 사용 전 보안과 접근 권한을 별도로 설계해야 한다.

`series_store.py`는 검사에 속한 시리즈의 식별자, 영상 종류와 촬영 부위 정보를 저장하고 조회한다. 현재 영상 종류와 촬영 부위는 값이 없는 상태도 허용한다. 시리즈 ID가 이미 다른 검사나 정보와 연결돼 있으면 덮어쓰지 않는다.

`study_image_store.py`는 로컬 PNG 또는 JPEG 원본을 검사에 속한 시리즈와 연결하고, 연결 정보를 통해 원본을 다시 연다. 해당 시리즈가 지정한 검사에 속하고 원본 파일의 해시가 일치하는지 확인한다. 파일이 없거나 손상된 경우와 Firestore 요청에 실패한 경우 각각 오류를 전달한다. `save_and_link_original`에서 원본 저장이 끝난 후 연결이 확인되지 않으면 `OriginalSavedLinkError`로 원본 키와 실패 원인을 전달하며, 이미 저장된 파일은 삭제하지 않는다. 통신 실패 시 서버에 연결이 실제로 저장됐는지 확인되지 않을 수 있으므로 동일한 연결로 재시도한다.

같은 사용자와 영상 ID의 검사, 시리즈와 원본이 모두 같으면 반복 연결을 허용한다. 같은 영상 ID로 다른 연결을 요청하면 충돌로 처리하며 기존 연결은 유지한다. 서로 다른 영상 ID가 동일한 파일을 참조할 때 한 로컬 파일을 재사용하지만 연결 정보는 각각 저장한다. 검사와 시리즈별 영상 목록은 사용자 전체 목록의 한 페이지에서 걸러내므로 빈 페이지라도 다음 토큰이 있으면 이어서 조회해야 한다.

기존 케이스와 사용자 인터페이스는 새 저장 함수와 연결하지 않았다. 기존에 시리즈 없이 저장한 개발용 영상 연결은 새 형식으로 자동 변환하지 않으며, 다시 연결하기 전까지 새 조회 함수에서 열 수 없다. 기존 원본 파일과 케이스는 변경하지 않는다.

설계서의 DICOM 원본 객체는 SOP UID, SOP Class UID, 내용 해시, 저장 참조와 프레임 수를 포함한다. 현재 샘플 영상 ID는 SOP UID가 아니며 DICOM UID 형식 검증, DICOM 파싱과 원본 저장은 구현하지 않았다. 같은 SOP UID와 같은 내용의 재사용, 같은 UID와 다른 내용의 충돌 보류는 DICOM 연동 시 구현하고 검증해야 한다. 식별 정보의 사용자 간 공유 범위, 구체적인 필드 형식과 오류 응답은 통합 구현 전에 확인한다. 현재 원본은 개발용 PC에만 저장되므로 다른 장치에서 파일을 여는 기능이나 JCloud 영구 보존을 의미하지 않는다.
