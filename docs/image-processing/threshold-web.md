# P01 임계값 분할 구현과 웹 연결

담당 B 명세 3장의 세 번째 후보인 임계값 분할을 기존 가우시안과 같은 처리 계약으로 추가했다. 기준 브랜치는 `feature/roi-statistics`(c238702)다.

## 1. 목적과 정의

임계값 분할은 기준 밝기 이상인 영역과 미만인 영역을 흑백으로 나누어 비교한다. 결과는 흰색(255)과 검은색(0)만 가지는 마스크이며, 뷰어와 ROI 계약을 유지하기 위해 같은 값을 RGB 세 채널에 넣는다.

$$
\text{mask}(x,y)=\begin{cases}255 & L(x,y)\ge t\\ 0 & L(x,y)<t\end{cases}
$$

- $L$은 Pillow `"L"` 변환(ITU-R 601-2 luma, $L \approx 0.299R + 0.587G + 0.114B$)으로 구한 0~255 정수 밝기다. ROI 통계의 `pillow_L_v1`과 같은 기준이다. 그래서 결과 ROI의 평균은 $255 \times$ (임계값 이상인 픽셀 비율)이 된다.
- 임계값과 **정확히 같은 밝기는 흰색**으로 분류한다(명세 3장의 제안).
- $t=0$이면 모든 픽셀이 흰색이다. $t=255$이면 밝기 255인 픽셀만 흰색이다.
- 컬러 영상도 L 밝기로 나눈다. 예를 들어 순수한 빨강 (255, 0, 0)은 L=76이므로 $t \le 76$일 때 흰색이 된다.

## 2. 함수 계약

구현은 [image_processing.py](../../image_processing.py)의 `threshold_segmentation`이다.

| 항목 | 내용 |
|---|---|
| 호출 | `threshold_segmentation(image, threshold=128)` |
| 입력 | `load_image`가 방향을 보정한 비어 있지 않은 RGB PIL 이미지 전체 |
| 출력 | 같은 크기의 새 RGB PIL 이미지. 픽셀은 (0,0,0) 또는 (255,255,255)이며 입력은 바꾸지 않는다 |
| 허용 임계값 | 정수 0~255. Python `int`와 NumPy 정수 스칼라 |
| 거절 | 범위 밖 정수는 `ValueError`. 실수(128.0 포함), bool, 문자열, None, 배열, 복소수는 `TypeError`. 실수를 몰래 반올림하지 않는다 |
| 알고리즘 ID/버전 | `"threshold_segmentation"` / `"1.0.0"` |

기본값 128은 현재 구현의 선택이며 과제가 정한 값이 아니다. 고정 임계값 방식이라 영상마다 적절한 값이 다르다. 조명이 고르지 않으면 한 값으로 원하는 영역을 나누기 어렵다. 자동 임계값(Otsu)이나 지역 임계값은 이번 범위가 아니다.

## 3. 웹 사용과 상태

1. 영상을 연 뒤 **처리 알고리즘**에서 **임계값 분할**을 선택한다. 임계값 입력만 나타나고 가우시안 강도는 숨겨진다.
2. 0~255 정수를 정하고 **임계값 분할 적용**을 누른다.
3. 결과 위에 알고리즘 ID, 버전과 실제 적용 임계값이 표시된다.

상태 규칙은 감마 브랜치와 같다. 설정값만 바꾸면 다시 계산하지 않고 안내를 띄운다. 알고리즘을 바꾸면 이전 결과를 지운다. 영상을 바꾸거나 로그아웃하면 기존 `viewer_processing_` 규칙으로 정리한다. 적용 기록은 `{source_id, algorithm_id, algorithm_version, parameters: {"threshold": t}}` 형태이고, 임계값은 정수로 남는다.

## 5. 남은 일과 한계

- 조건별 비교 실험은 6장에 정리했다.
- 원본/결과 높이 정렬과 실패 원인 `logging`은 통합 이후 `develop`(#22)에 반영됐다.
- 결과 마스크는 8비트 표시 밝기를 기준으로 한다. 의료적인 영역 분할이나 CT 값 기준의 분할이 아니다.
- 고정 임계값만 지원한다. 자동 임계값(Otsu)과 지역 임계값은 범위가 아니며, 실험에서는 비교 참고값으로만 사용했다.

## 6. 조건별 비교 실험

감마 실험과 같은 입력 5종(정상, 노출 부족, 노출 과다, 잡음 σ=20 합성 차트와 Lenna 흑백)에 임계값 64, 100, 128, 160, 200을 각각 적용했다. 입력별로 OpenCV Otsu가 고른 값도 **참고값으로** 함께 적용했다. 실행 방법은 `uv run --locked python experiments/gamma_threshold_experiment.py`이고, 결과는 [results/threshold](results/threshold/)에 있다([요약](results/threshold/summary.md), [CSV](results/threshold/metrics.csv), [비교 이미지](results/threshold/comparison.png), [명세](results/threshold/manifest.json)).

### 정답과 측정

- **정답 마스크**: 깨끗한 정상 차트 본문(밝기 띠 아래 224행)에서 L ≥ 128인 밝은 구조(원, 사각형, 2픽셀 선, 밝은 블록)다. 노출이나 잡음을 바꿔도 구조의 위치는 같으므로 같은 정답을 쓴다.
- **IoU**: 결과 흰색 영역과 정답의 교집합 ÷ 합집합
- **FPR**: 배경을 흰색으로 잘못 고른 비율
- **FNR**: 구조를 놓친 비율
- **흰색 비율**: 본문 중 흰색인 비율. ROI 평균(= 255 × 흰색 비율)과 분산도 함께 기록했다.

### 결과 (발췌, 전체는 summary.md)

| 입력 | t=64 | t=100 | t=128 | t=160 | t=200 | Otsu 참고 |
|---|---|---|---|---|---|---|
| chart_normal | 0.934 | **1.000** | **1.000** | **1.000** | 0.273 | t=75, 0.934 |
| chart_under | **1.000** | 0.070 | **0.000** | 0.000 | 0.000 | t=34, 0.934 |
| chart_over | 0.223 (FPR 1.0) | 0.223 | 0.223 | 0.223 | **1.000** | t=174, 0.934 |
| chart_noise20 | 0.396 (FPR 0.438) | 0.915 | **0.996** | 0.886 (FNR 0.114) | 0.324 | t=124, 0.996 |
| lenna_gray (흰색 비율) | 0.828 | 0.661 | 0.502 | 0.241 | 0.070 | t=119, 0.550 |

값은 IoU다. 잡음 입력의 물체 ROI(원 내부) 흰색 결과는 t=128에서 평균 254.2·분산 202.6이고, t=160에서 평균 213.1·분산 8931.6이다. 구멍이 많아진 것이 분산으로 드러난다.

### 해석

- **효과가 있었던 조건**: 정상 노출에서는 배경(60)과 물체(180) 사이의 임계값 100~160이 모두 정답과 완전히 일치했다(IoU 1.0). 밝기 분포가 두 덩어리로 뚜렷이 나뉘고, 그 사이에 임계값이 있을 때 잘 동작한다. 잡음 σ=20에서도 두 덩어리의 한가운데에 가까운 t=128은 IoU 0.996으로 거의 유지됐다.
- **실패한 조건 — 노출 변화**: 같은 장면이라도 노출이 바뀌면 적절한 임계값이 크게 이동한다.
  - 노출 부족에서는 물체가 81이 되어 t=128 이상이 모두 실패했다(IoU 0, FNR 1.0).
  - 노출 과다에서는 배경이 167이 되어 t=64~160 모두 화면 전체를 흰색으로 만들었다(FPR 1.0).
  - **고정 임계값 하나로는 노출이 다른 영상을 함께 다룰 수 없다.** Otsu 참고값은 34, 75, 174로 노출을 따라 움직였다.
- **잡음의 영향**: 임계값이 한쪽 밝기 덩어리에 가까울수록 잡음 때문에 잘못 분류되는 픽셀이 늘어났다.
  - t=64에서는 배경 잡음이 흰 점으로 나타났다(FPR 0.438).
  - t=160·200에서는 물체 안에 검은 구멍이 생겼다(FNR 0.114, 0.676).
  - 픽셀 하나씩 독립적으로 판정하므로 잡음 점을 지우지 못한다. 앞단의 가우시안 평활화가 필요한 경우다.
- **정답 정의와의 차이**: Otsu 참고값은 정상 차트에서 75를 골랐다. 그래서 어두운 저대비 패치(75)까지 흰색으로 분류해 IoU가 0.934였다. 자동 방법도 "무엇을 구조로 볼지"의 목적과 다를 수 있다.
- **자연 영상**: Lenna는 정답이 없어서 흰색 비율만 기록했다. 임계값을 64에서 200으로 올리는 동안 흰색 비율이 0.83에서 0.07로 연속적으로 변한다. 밝기 분포가 두 덩어리로 나뉘지 않아서, 하나의 "맞는" 임계값이 정해지지 않는다.
- **한계**: 합성 차트의 정답은 실험용으로 정한 것이다. 의료적 영역 분할 정확도를 뜻하지 않는다. 조명 불균일(한 영상 안에서 밝기가 변하는 경우)은 이번 입력에 포함하지 않았다.
