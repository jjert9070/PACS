# P01 감마 보정 구현과 웹 연결

담당 B 명세 3장의 두 번째 후보인 감마 보정을 기존 가우시안과 같은 처리 계약으로 추가했다. 기준 브랜치는 `feature/roi-statistics`(c238702)이며, 병합은 팀 리뷰 후 진행한다.

## 1. 목적과 정의

감마 보정은 픽셀마다 밝기값을 거듭제곱 곡선으로 바꾸어 중간 밝기의 표현을 조절한다. 주변 픽셀을 섞지 않으므로 가우시안처럼 경계가 흐려지지 않는다. 대신 밝기 단계가 압축되는 구간에서는 세부 차이가 줄어든다.

$$
\text{out}=\operatorname{rint}\left(255\cdot\left(\frac{\text{in}}{255}\right)^{\gamma}\right)
$$

- γ < 1이면 중간 밝기가 밝아지고, γ > 1이면 어두워진다. γ = 1이면 원본과 같다.
- 0과 255는 모든 γ에서 그대로 유지된다. 곡선은 단조 증가하므로 밝기 순서가 뒤바뀌지 않는다.
- `np.rint`는 정확히 중간인 값을 짝수 쪽으로 반올림한다. 가우시안 실험과 같은 정책이다.
- 예: γ=2이면 128 → 64, 64 → 16. γ=0.5이면 128 → 181.

## 2. 함수 계약

구현은 [image_processing.py](../../image_processing.py)의 `gamma_lut`, `gamma_correction`이다.

| 항목 | 내용 |
|---|---|
| 호출 | `gamma_correction(image, gamma=1.0)` |
| 입력 | `load_image`가 방향을 보정한, 비어 있지 않은 RGB PIL 이미지 전체 |
| 출력 | 같은 크기의 새 RGB PIL 이미지. 입력 픽셀은 바꾸지 않음 |
| 허용 γ | 유한한 0.1~10. Python `int`/`float`와 NumPy 정수·실수 스칼라 |
| 거절 | 범위 밖 값, NaN, 무한대는 `ValueError`. bool, 문자열, None, 배열, 복소수는 `TypeError` |
| 처리 | 256칸 조회표(LUT)를 만들고 R, G, B 각 채널에 같은 표를 독립 적용 |
| 알고리즘 ID/버전 | `"gamma_correction"` / `"1.0.0"` |

γ 범위 0.1~10은 팀 정책이며 과제가 정한 값이 아니다. 이 범위를 벗어나면 대부분의 8비트 밝기가 0이나 255로 몰린다. 채널을 독립적으로 바꾸므로 회색은 회색으로 유지된다. 채도가 높은 색은 색상이 약간 달라질 수 있다. 이 기능은 8비트 표시값을 바꿀 뿐이며 DICOM 윈도우 조절이나 CT 값 변환이 아니다.

## 3. 웹 사용과 상태

1. 영상을 연 뒤 왼쪽 **처리 알고리즘**에서 **감마 보정**을 선택한다. 감마 설정만 표시되고 가우시안 강도는 숨겨진다.
2. γ를 0.1~10 범위로 정하고 **감마 보정 적용**을 누른다.
3. 오른쪽 결과 위에 알고리즘 ID, 버전과 실제 적용 γ가 표시된다. ROI를 적용했다면 원본과 결과의 평균과 분산을 비교할 수 있다.

화면 상태 규칙은 다음과 같다.

- 설정값만 바꾸면 다시 계산하지 않는다. 대신 "현재 표시 결과는 적용 γ=…" 안내를 띄운다.
- 알고리즘을 바꾸면 이전 결과, 적용 기록과 오류를 지운다. 다른 알고리즘의 결과가 새 선택의 결과처럼 보이지 않게 하기 위해서다.
- 영상 교체와 로그아웃 시 정리하는 동작은 기존 `viewer_processing_` 규칙을 그대로 따른다.

세션의 적용 기록은 `{source_id, algorithm_id, algorithm_version, parameters}` 형태다. 기존 가우시안 기록은 `radius`를 최상위에 두었지만, 이제 `parameters`가 `{"radius": σ}` 또는 `{"gamma": γ}`를 담는다. 따라서 C가 `ProcessingRecord.parameters`로 그대로 사용할 수 있다. 처리 결과를 케이스에 저장하는 연결은 이번 범위가 아니다.

## 5. 남은 일과 한계

- 조건별 비교 실험은 6장에 정리했다.
- 임계값 분할과의 알고리즘 선택 통합, 원본/결과 높이 정렬은 `develop`(#22)에 반영됐다.
- γ는 영상 전체에 하나의 곡선을 적용한다. 영역마다 다른 보정(CLAHE 등)이나 자동 γ 선택은 범위가 아니다.
- 8비트 표시값을 바꾸는 처리이며 DICOM 원본 저장값이나 CT HU를 바꾸지 않는다.

## 6. 조건별 비교 실험

밝기, 잡음, 대상이 서로 다른 입력에 γ 0.5, 0.8, 1.0, 1.5, 2.2를 각각 독립 적용했다. 실행 방법은 `uv run --locked python experiments/gamma_threshold_experiment.py`이고, 결과는 [results/gamma](results/gamma/)에 있다([요약](results/gamma/summary.md), [CSV](results/gamma/metrics.csv), [비교 이미지](results/gamma/comparison.png), [명세](results/gamma/manifest.json)).

### 입력과 측정

| 입력 | 내용 |
|---|---|
| `chart_normal` | 정답 위치를 아는 256×256 합성 차트. 위 32행은 0~255 밝기 띠, 배경 60. 밝은 물체(원, 사각형, 2픽셀 선) 180. 어두운 저대비 패치 75(배경 60). 밝은 저대비 패치 225(주변 210) |
| `chart_under` / `chart_over` | 같은 차트의 노출 부족(×0.45)과 노출 과다(255−(255−x)×0.45) |
| `chart_noise20` | 정상 차트 + 평균 0, 표준편차 20의 밝기 잡음(시드 20261115, 세 채널 동일) |
| `lenna_gray` | 저장소의 Lenna를 256×256, Pillow L 흑백으로 변환한 자연 영상(가우시안 실험과 같은 처리) |

측정한 값은 다음과 같다. 모두 Pillow L 밝기 기준이며 ROI 통계는 웹과 같은 `compare_roi`(모집단 분산)를 사용했다.

- 평균 밝기
- **국소 대비**: 패치 평균 − 주변 평균
- **밝기 단계 수**: 밝기 띠 한 줄에서 서로 다른 출력값의 개수. 줄어든 만큼 입력 단계가 하나로 합쳐진 것이다.
- ROI 평균과 분산

### 결과 (발췌, 전체는 summary.md)

| 입력 | γ | 평균 밝기 | 어두운 패치 대비 | 밝은 패치 대비 | 밝기 단계 수 (전체/어두운/밝은) |
|---|---|---|---|---|---|
| chart_normal | 1.0 | 93.9 | 15.0 | 11.1 | 256 / 64 / 64 |
| chart_normal | 0.5 | 148.5 | 14.0 | 6.7 | 192 / 64 / **35** |
| chart_normal | 2.2 | 43.7 | **6.0** | **20.8** | 184 / **13** / 64 |
| chart_under | 1.0 | 42.2 | 7.0 | 5.2 | 116 / 29 / 30 |
| chart_under | 0.5 | 99.6 | **10.0** | 3.7 | 108 / 29 / 24 |
| chart_under | 2.2 | 7.5 | **1.0** | 3.7 | 45 / **3** / 22 |
| chart_over | 1.0 | 182.3 | 7.0 | 5.2 | 116 / 30 / 29 |
| chart_over | 2.2 | 124.9 | **10.0** | **10.4** | 116 / 30 / 29 |
| lenna_gray | 0.5 / 1.0 / 2.2 | 174.3 / 124.2 / 62.4 | - | - | - |

잡음 입력의 물체 ROI(밝기 180, 잡음 분산 373.6)는 γ=0.5에서 분산이 **134.0**으로 줄고, γ=2.2에서 **788.3**으로 커졌다.

### 해석

- **효과가 있었던 조건**
  - γ < 1은 어두운 영역의 단계 간격을 넓힌다. 노출 부족 차트에서 γ=0.5는 어두운 패치 대비를 7 → 10으로 키웠고, 평균 밝기를 42 → 100으로 올렸다.
  - γ > 1은 밝은 영역을 넓힌다. 노출 과다 차트에서 γ=2.2는 밝은 패치 대비를 5.2 → 10.4로 두 배로 만들었다.
  - 즉 **영상의 밝기 분포가 몰린 쪽에 맞춰 γ 방향을 고를 때** 효과가 있다.
- **정보가 손실된 조건**
  - γ는 곡선의 기울기가 1보다 작은 구간에서 여러 입력 단계를 한 출력값으로 합친다.
  - γ=2.2는 정상 차트의 어두운 구간(입력 0~63) 단계를 64 → 13개로 줄였고, 노출 부족 차트에서는 3개만 남겼다. 어두운 패치 대비도 15 → 6, 7 → 1로 사라졌다.
  - 반대로 γ=0.5는 밝은 구간(192~255) 단계를 64 → 35개로 줄였다.
  - 단계 수는 한번 합쳐지면 반대 방향 γ를 다시 적용해도 되살아나지 않는다(8비트 정수 조회표).
- **효과가 부족하거나 부작용이 있던 조건**
  - 정상 차트의 어두운 패치(60 대 75)는 γ=0.5에서 대비가 15 → 14로 오히려 약간 줄었다. 이 밝기 구간에서 곡선 기울기가 거의 1이기 때문이다. γ<1이 모든 어두운 영역의 대비를 키우는 것은 아니다.
  - 감마는 잡음도 함께 늘리거나 줄인다. 잡음 차트의 밝은 물체 영역에서 γ=2.2는 잡음 분산을 약 2.1배(373.6 → 788.3)로 키웠다. 대비를 위해 γ를 키우면 그 구간의 잡음도 커진다.
  - 원 영상 전체에 같은 곡선을 쓰므로, 어두운 곳과 밝은 곳을 동시에 개선할 수 없다(γ=0.5는 어두운 쪽, γ=2.2는 밝은 쪽만).
- **한계**
  - 합성 차트와 Lenna 한 장으로 한 교육용 실험이다. 보편적인 최적 γ나 진단 품질을 뜻하지 않는다.
  - 대비는 고정 영역의 평균 차이다. 사람의 시각 품질이나 의료적 가독성은 측정하지 않았다.
