# 담당 A 보기와 B/C 연결 검증

이 변경은 BC 통합 기준 `07059fb` 위에 A의 보기 조작과 밝기·대비를 연결한 검토용 변경이다. `feature/viewer-abc-controls`에서 B/C 담당자에게 연결 계약 검토를 요청한다.

## 입력과 상태 계약

- `ViewerSource.original_bytes`는 기본값이 빈 바이트인 키워드 전용 필드다. `render_viewer`는 저장 원본도 `load_image(name, original_bytes)`로 다시 검사하고 원본 해시가 일치할 때 표시한다.
- C의 `ProcessingRecord`는 기존 `validate_processing`으로 원본 참조·크기·ROI 통계 계약을 검사한다. B의 직접 콜백 결과는 `viewer_processing_applied.source_id`가 현재 원본과 같은지 검사한다. 메타데이터 없는 범용 콜백은 현재 입력의 복사본으로 호출하는 기존 동기 방식으로 사용한다.
- 이전 `stored_result` 호출은 `stored_result_source_id`에 원본 해시를 함께 전달한다. 실제 앱의 C 저장 결과는 `stored_processing`으로 검증한다.
- `roi_controls(source)`는 B가 검증한 원본 좌표를 반환한다. 영상 교체 시 `viewer_processing_*`, `viewer_roi_*`, 현재 처리 기록을 정리한다. 같은 바이트는 같은 원본으로 식별한다.
- `allow_source_change()`는 C의 `_dirty()`와 기존 `case_record_discard` 선택을 사용한다. 미저장 변경이 있으면 기존 원본과 상태를 표시하고 전환을 안내한다. 입력 자체가 손상된 경우에는 오류와 함께 표시를 중단한다.
- 보기 초기화는 보기 키만 기본값으로 돌린다. 로그인 종료 시 앱의 기존 `clear_session()`이 뷰어와 케이스 상태를 정리한다.

## 표시 순서

ROI 테두리를 전체 원본 복사본에 그림 → 원본 좌표 크롭 → 시계 방향 회전 → 표시 축 기준 반전 → 미리보기 축소 → 표시 밝기·대비 순서다. ROI가 크롭과 겹치지 않으면 선택과 통계를 유지하고 현재 보기에 표시되지 않는다고 안내한다. 처리 결과 영상 슬롯을 제목 바로 아래에 유지한다.

밝기·대비는 기본 100%, 범위 50~150%, 5% 단위다. 밝기를 곱한 뒤 127.5를 기준으로 대비를 조절한다. B의 통계와 C의 저장에는 표시용 픽셀을 넘기지 않는다.

`python -m unittest discover`로 전체 160개 검사를 통과했다. Python 3.12.16, Streamlit 1.55.0, Pillow 12.3.0, NumPy 2.2.6, OpenCV 4.12.0.88 환경이다. 테스트는 기존 B/C 모듈과 임시 파일을 사용하며 Firestore 응답과 로그인 세션은 모의 처리한다.

브라우저에서는 합성 예시 640×480, 가우시안 기본 강도, ROI `(0,0,8,6)`으로 확인했다. 밝기 105%, 대비 95%, 회전 90°, 좌우 반전을 적용해도 원본과 결과의 평균 0.875000, 모집단 분산 0.609375가 같았다. 4배 확대 후 ROI가 보기 밖이라는 안내와 선택 유지, 메모 입력 후 영상 전환 차단을 확인했다.

## 리뷰 요청

B는 `roi_controls`, 원본 참조 검사, 처리 결과 슬롯을 확인한다. C는 저장 바이트 재검사, `_dirty()` 재사용과 폐기 선택, 저장 결과의 참조 입력을 확인한다. 공동 계약은 이 PR에서 검토 후 확정한다. 병합은 사용자 지시에 따라 보류 중이다.
